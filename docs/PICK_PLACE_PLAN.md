# GPU 병렬 Pick & Place 실행 계획

사용자가 2026-09-12에 최종 목표를 집기·운반·배치·해제 전체로 확정하고 GPU 실행을 요청했다. 기존 LiftCube의 측정과 체크포인트를 보존하고 `SO101-PickPlace-v0`를 별도로 등록한다.

## 계약 변경 이유와 영향

기존 `common/task_spec.json`은 LiftCube v0.1.0의 정본으로 유지한다. 신규 태스크 정본은 `common/pick_place_spec.json`이다. 실행기는 태스크 ID로 계약을 선택하고 해당 SHA를 기록한다. 입력 차원이 달라 기존 Lift checkpoint를 신규 정책으로 그대로 재개할 수 없다. Ubuntu 교차평가는 신규 계약을 적용하기 전까지 미검증이다.

## 사전 등록 설계값

- 4cm 큐브, 상태 기반 6차원 관절 delta PPO, physics 120Hz / policy 30Hz.
- 에피소드 20초, 시작 위치와 목표 위치를 각각 환경별로 샘플링한다.
- 양쪽 손가락 접촉 상태에서 8cm 들어 올려 0.2초 유지해야 파지 이력을 인정한다.
- 목표 중심 XY 오차 3cm 이하, 큐브 중심 높이는 테이블 위 2cm에서 1cm 이내.
- 목표 위에서 선속도 0.05m/s 이하, 각속도 0.5rad/s 이하로 내려놓으며 해제해야 한다.
- 그리퍼 개방, 손끝 8cm 이상 이격, 양쪽 손가락 접촉 해제 상태에서 1초 안정 유지해야 최종 성공이다.
- 목표 밖/공중에서 접촉을 잃으면 운반 이력이 무효다. 밀기·잡고 버티기·던지기 경로는 성공 불가.
- 한쪽 손가락만 닿은 전환 구간은 목표 위의 저속 배치에서만 허용한다. 목표 밖의 한 손가락 밀기도 운반 이력을 무효화한다.
- 목표 밖 운반 중에는 초기 큐브 중심보다 1cm 이상 높아야 한다. 한 번 든 뒤 양손으로 테이블에 끌어 옮기는 경로도 무효다.
- 해제 직전 접촉 샘플도 목표 위·저속이어야 한다. 두 정책 샘플 사이에 던져 충돌한 뒤 정착하는 경로를 차단하며, 직전 release-ready 상태를 관측에 포함한다.
- 이력 판정은 정책 30Hz가 아니라 매 물리 step 120Hz에서 수행한다. PP 환경에만 Isaac Lab 2.1.1의 step 루프를 외부 어댑터로 보존하고 `scene.update` 직후 이력을 갱신한다. 이산 물리 샘플보다 짧은 연속시간 사건까지 관측한다고 주장하지 않는다.
- 최종 성공 시 1회 보상 1,000을 지급한다. JSON의 양의 shaping rate 합계 145, policy 30Hz, 할인율 0.99에서 지속 보상의 무한지평 상한은 약 483.33이다. 즉시 성공할 수 있는데 보상을 얻으려고 지연하는 유인을 차단한다. 이 값들은 성능 측정이 아닌 설계값이며 보상·할인율도 계약 SHA에 포함한다.
- 위 값은 측정값이 아닌 초기 설계값이다. 조건 변경 시 기존 실행을 보존하고 계약 버전을 올린다.

## 실행과 검증 순서

1. 계약, GPU 벡터 상태기계, 환경별 목표·reset·보상·관측 구현. 전체 성공만 종료 조건으로 사용.
2. 순수 tensor 회귀 테스트: 정상 순서, 밀기, 던지기, 잡고 유지, 고속 해제, 높이 오류, 부분 reset, 환경 간 상태 격리.
3. 코드 리뷰 후 clean source commit에서 1환경 1,000 physics step, 64환경 10,000 physics step, 실제 접촉 및 부분 reset 검증.
4. 64환경 PPO 10 iteration과 checkpoint 재시작으로 GPU 학습 경로 검증.
5. 256/512/1024환경에서 같은 짧은 학습 예산으로 처리량·VRAM 비교. 다른 GPU 작업이 있으면 시작하지 않는다.
6. 선택한 환경 수에서 scratch PPO 학습을 실행하고 별도 평가기로 전체 에피소드 성공률·실패 단계를 측정한다. 학습 실행 성공과 정책 성공을 구분한다.
7. 본 실험은 seed 0/1/2, 조건별 각 200에피소드. 보상 ablation·DR·MuJoCo 비교는 PPO 기준선 이후에 순서대로 수행한다.

## 승인·완료 증거

코드 리뷰, 계약 테스트, 물리 실행 보고서, GPU/CPU/VRAM 측정, 체크포인트와 SHA, 독립 평가를 보존한다. success 판정 합성 fixture는 정책이 작업을 수행했다는 증거로 사용하지 않는다. 실물은 범위 밖이다. 현재 작업에서는 로컬 커밋까지 수행하며 원격 push는 별도 요청 시 수행한다.
