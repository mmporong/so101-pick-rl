# 시연 기반 병렬 강화학습 실행 계획

2026-09-18 사용자 승인으로 기존 scratch PPO 제한을 확장한다. 기존 4cm 과제,
체크포인트, 미커밋 파지 진단은 보존한다. 새 실험은 원본 시연의 3cm 박스 배치
과제와 절대 목표각 제어를 기준으로 분리한다. 실물 로봇은 실행하지 않는다.

## 단계와 완료 근거

1. 원본 성공 10회와 Mimic 500회의 숫자 데이터, 초기 상태, 메타데이터를
   읽기 전용으로 추출한다. RGB 원본은 수정하지 않는다. 원본별 출처, 숫자
   데이터 해시, 프레임 정렬 검사, 제외 사유를 기록한다.
2. 같은 초기 상태에서 저장된 모터 목표각을 재생한다. 관측된 다음 관절각을
   목표각으로 대체하지 않는다. 시뮬레이터 버전, 60Hz 시간축, 큐브 자산,
   그리퍼 구동 한계가 다른 환경에 재생 성공을 자동 전이하지 않는다.
3. 재생이 검증된 환경에서 상태 관측으로 actor를 지도 학습한다. 절대 목표각
   라벨의 관절 한계 보정량과 급변 시연을 보고한다. 학습/검증을 에피소드로
   나누고, 공통 원본 시연에서 파생된 검증을 OOD라고 부르지 않는다.
4. 초기 actor에서 실제 다중 환경 PPO를 실행한다. 시연 재생, Mimic 생성,
   BC와 PPO의 업데이트 수를 구분한다. 물체 부착이나 강제 상태 이동은 reset
   외에 사용하지 않는다. 물리 검증에 실패한 실험을 확대하지 않는다.
5. 고정된 평가 조건에서 전체 Pick & Place와 실패를 보고한다. 열기, 접근,
   파지, 들기, 운반, 배치, 해제 및 안정 유지가 확인되지 않으면 완료가 아니다.
   영상과 대용량 데이터는 Git에 넣지 않는다.

## 확인된 실행 환경

- Windows: Isaac Sim 4.5 / Isaac Lab 2.1.1, RTX 3060 12GB.
- ASUS 원본 환경 실측: Isaac Sim 5.1.0 / Isaac Lab 2.3.0,
  PyTorch 2.7.0+cu128, RTX 5050 Laptop.
- Mimic HDF5 메타데이터: physics dt=1/60초, decimation=1.
  원본 10개 파일의 env_args에는 dt/decimation이 없다. 원본 기록 주기는
  별도 생성 기록으로 입증해야 하며 Mimic의 값을 원본 메타데이터로 인용하지 않는다.
- 원본 위치: ASUS의 `/data/lim/leisaac/datasets/pick_cube_into_box_source_10_20260911.hdf5`.
- Mimic 위치: `/data/lim/leisaac/outputs/mimic_vision224_500_20260913/raw/`.
- 병행 작업이 원격 저장소에서 실행 중이므로 원격 소스/모델을 덮어쓰거나
  타 작업 프로세스를 종료하지 않는다. 별도 출력만 사용한다.

원격 `contract_hardening_20260918/replay_stable_release/evaluation.json`에서
demo_0/1/2의 stable_release_v2 재생 3/3을 읽었다. 이 수치는 기존 작업의
원본 환경 재생 결과이며 새 정책, Windows 환경, 접촉 침투 감사의 통과가 아니다.

## 현재 진행

2026-09-19 재접속 후 원본 성공 10회·5,640프레임과 Mimic 500회·277,447프레임의
숫자 데이터 전송을 완료했다. 두 HDF5의 원격/로컬 SHA-256, 원본 stat 불변,

근거는 `reports/windows/demo_transfer_20260919.json`이다.

로컬 사본은 `artifacts/demo_warmstart_20260919/`에 있다. RGB 영상은 원본에
남겼다. 사용자가 노트북에서 별도 작업을 시작하므로 이 실행은 노트북 GPU를

시뮬레이터 버전 차이가 있으므로 원본 환경의 재생 성공을 Windows에 전이하지 않는다.
Windows GPU 물리 재생과 제한 목표각 비교를 실행했다. BC와 병렬 PPO는 아직 실행하지 않았다.

숫자 추출 파일은 원본의 이미지 없는 복사본이며 학습 준비가 끝난 데이터가 아니다.
`demo_action_contract.aligned_targets`는 목표각을 T−1 전이에 정렬하고 범위·급변을
검사하는 유틸리티다. 별도 `isaaclab/scripts/replay_demo_box.py`는 원본 장면의
절대 목표각 재생과 실제 상태·접촉 추적을 수행한다. 학습용 state-action loader,
BC와 PPO 연결부는 아직 구현하지 않았다. 기존 학습 진입점에 이 파일을 입력해 실행하지 않는다.
학습 어댑터는 배열의 6열을 믿고 연결하지 말고 시뮬레이터 관절 이름·순서를
`JOINT_NAMES`와 대조해야 한다. 관절 한계의 출처와 SHA-256도 실행 기록에 남긴다.
범위를 벗어난 목표각은 현재 감사 도구에서 거부한다. 보정이 필요하면 raw를
보존한 별도 파생 라벨에 보정량·제외 기준을 기록하고 재생으로 검증해야 한다.

## 전체 순서 검증에서 추가로 확인한 문제 — 2026-09-19

앞서 기록한 demo_1 후보는 **정상 내려놓기 통과 시연이 아니다**. 상자 바닥에
닿기 전에 그리퍼가 열렸고, 큐브가 떨어진 뒤 안정화되었다. 기존의 상자 위치·
안정 유지 진단만으로는 이를 구별할 수 없었다. 앞 절의 1/10은 부분 진단 결과로
유지하며, 학습 적격 데이터 1개를 확보했다는 뜻으로 읽지 않는다.

새 `configs/evaluation/demo_box_replay_gate.json`은 재생 감사용 기준이며 아직
DemoBox 학습 계약이 아니다. 열린 접근 → 패드 사이 양면 파지 → 8cm 상승·
0.2초 연속 파지 → 상자 바닥 지지 → 저속 해제 → 열린 손 후퇴·1초 안정 유지의
순서를 검사한다. 침투 1mm, 손목 75도, 하중 접촉 0.2N 기준은 유지한다.
벽 접촉도 침투 감사에 포함하며, 순간 접촉 손실을 시간 평균으로 숨기지 않는다.

보정 제어는 실제 관절 목표각만 보낸다. 큐브·관절 상태를 실행 중 덮어쓰거나
큐브를 손에 고정하지 않는다. 실패 표본을 저장한 뒤 해당 보정 실행을 끝내며,
나중에 떨어져 안정화된 상태가 앞선 실패를 취소하지 못한다.

추가 비교에서 확인한 사항:

- 원본 상자에서 기울어진 그리퍼가 벽에 걸렸다. 벽을 무시하거나 제거하지 않았다.
- 손목 한계 밖의 IK 결과를 마지막에 잘라내던 방식은 다른 관절의 보상 움직임을
  그대로 실행하는 문제가 있었다. 한계에 닿은 관절을 고정하고 나머지 명령을
  다시 계산하도록 보정 제어를 바꿨다.
- 별도 환경 비교로 상자 바닥과 네 벽을 x/y 각각 -0.05m 옮겼다. 원본 위치의
  성공으로 계산하지 않는다. 이 조건에서는 양면 파지를 유지한 채 상자 바닥의
  지지 접촉까지 도달했다. 아직 전체 동작이나 정책의 성공을 뜻하지 않는다.
- 60Hz 명령은 유지하면서 물리 계산만 240Hz로 바꾸는 옵션을 추가했다. 접촉·
  속도·침투와 순서 판정은 모든 물리 스텝에 적용한다. 유효 시간 간격과 별도
  기준 해시를 기록하고, 변경된 상태를 원본 관측과 섞지 않는다.
- 바닥 지지 뒤 파지 토크 상한을 서서히 낮추는 비교는 그리퍼 열기까지 진행했으나,
  `controlled_place13_supported_240hz`는 부분 접촉이 풀릴 때 각속도 기준을
  충족하지 못해 3,106번째 물리 스텝에서 실패했다. BC/PPO는 실행하지 않았다.

원본 숫자 데이터, 자산, 이전 체크포인트는 보존했다. 비교별 원시 기록과 실행
코드 사본은 Git 비추적 `artifacts/demo_warmstart_20260919/controlled_place*/`에 있다.
추가 비교가 통과하더라도 먼저 같은 조건의 재현성과 별도 표본을 확인해야 하며,
그 후에 DemoBox 학습 계약과 BC·64환경 smoke·PPO를 연결한다.

## 추가 재생 검증 — 2026-09-21

학습 적격 시연은 아직 확보하지 못했다. BC와 병렬 PPO는 `not_run`이다.
실행별 코드 사본과 보고서·trace 해시는
`reports/windows/demo_sequence_status_20260921.json`에 기록했다.
26개 개발 비교의 29개 에피소드 실행이며, 같은 시연의 반복이 포함되어 있으므로
정책 성공률 평가로 해석하지 않는다. 모든 실행 코드 사본의 해시를 대조했다.
각 실행의 판정 설정 해시가 다를 수 있으며 과거 판정을 최신 설정으로 덮어쓰지 않았다.

- 22번 비교는 바닥 지지까지 도달했지만 그리퍼와 상자 앞벽 사이 약 20N,
  jaw와 바닥 사이 약 9N 접촉이 관찰되었다. 5,291번째 스텝에서 파지가 풀릴 때
  큐브 각속도가 급증했다. 작은 침투량만으로 끼임이 없다고 판단할 수 없다.
- 23번의 느린 열기도 7,148번째 스텝에서 실패했다. 24·25번의 6mm·3mm 파지
  높이 보정은 연속 상승 파지에 도달하지 못했다. `cube_pushed_before_grasp`는
  이전에 잠깐 성립한 파지가 접촉 손실로 초기화된 경우도 포함하므로,
  이 라벨만으로 전체 구간에 파지가 전혀 없었다고 해석하지 않는다.
- 25번부터는 손과 상자의 합산 접촉력 0.2N 초과도 별도로 거부한다.

## 초기화와 목표 시연 재감사 — 2026-09-22

이번 비교는 추가 학습이 아니라 실패 원인 분리다. 전체 픽앤플레이스는 아직
해결하지 못했다. 근거와 artifact 해시는
`reports/windows/demo_foundation_20260922.json`에 고정했다.

1. Mimic 500개 모두 측정 관절각 0에서 시작한다. 그런데 최초 이전 목표각과
   다음 실행 목표각의 차이가 495개에서 1rad 이상이어서 기존 BC 필터가 첫
   전이를 제외한다. 평가기는 이 초기 관측에서 정책을 호출했고, 잔차 정책은
   초기 이전 목표각을 다음 명령의 기준으로 사용했다. 학습에서 빠진 초기
   구간을 평가에서 요구한 불일치를 확인했다.
2. `--reset-bootstrap home-open-one-step` 진단 옵션을 추가했다. 첫 명령만
   `[0, 0, 0, 0, 0, 1.35] rad`로 실행하고 다음 스텝부터 같은 정책을 사용한다.
   실제 물리 스텝을 수행하며 상태/관측을 덮어쓰지 않는다. 첫 스텝도 접촉 및

3. 같은 체크포인트·64개 초기 상태·900스텝·접촉 채널로 수정 전후를 비교했다.

   진단은 2/64로 같았고 원본 상자 안정화 진단은 2/64에서 1/64로 줄었다.
   따라서 초기화 문제를 전체 실패의 유일한 원인으로 보거나 이 옵션을
   성공률 개선책으로 채택하지 않는다.
4. 수정 뒤 상승한 17/400을 같은 64환경 안에서 다시 접촉 검사했다. 두 표본
   모두 전체 순서 검사에 실패했다. 17은 지지 전 파지 상실/해제와 침투,
   400은 파지 전 이동과 침투가 남았다. 접촉 검사 대상을 바꾼 두 실행의

현재 BC는 release 전까지만 학습한다. 기존 데이터의 접근·파지·운반 구간은
재사용 후보로 남기되, 정상 내려놓기·열기·후퇴의 교사 구간은 별도로 검증해야

## 데이터 접근 재개 — 기존 안내

원본에는 실패 1회가 섞여 있으므로 성공 10회 추출 때만
`--skip-failed-episodes`를 명시한다. 제외된 시연은 manifest에 남긴다.
500회 raw 묶음은 성공 shard만 선택하고 실패 파일은 별도 보존한다.
모든 출력에는 새 이름을 사용하며, 원본 HDF5·기존 출력·원격 소스를 수정하지 않는다.

HDF5 검사에는 Isaac Sim에 이미 설치된 h5py를 사용한다. Windows의 일반
Python 3.14에는 h5py가 없어 해당 테스트를 실행할 수 없으며, 전역 패키지는 설치하지 않는다.
