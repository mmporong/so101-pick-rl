# 시연 기반 병렬 강화학습 실행 계획

2026-09-18 사용자 승인으로 기존 scratch PPO 제한을 확장한다. 기존 4cm 과제,
체크포인트, 미커밋 파지 진단은 보존한다. 새 실험은 원본 시연의 3cm 박스 배치
과제와 절대 목표각 제어를 기준으로 분리한다. 실물 로봇은 실행하지 않는다.

## 단계와 완료 근거

1. 원본 성공 10회와 Mimic 500회의 숫자 데이터, 초기 상태, 메타데이터를
   읽기 전용으로 추출한다. RGB 원본은 수정하지 않는다. 원본별 출처, 숫자
   데이터 해시, 프레임 정렬 검사, 제외 사유를 기록한다.
2. 같은 초기 상태에서 저장된 모터 목표각을 재생한다. 관측된 다음 관절각을
   목표각으로 대체하지 않는다. 시뮬레이터 버전, 60Hz 시간축, 큐브 자산,
   그리퍼 구동 한계가 다른 환경에 재생 성공을 자동 전이하지 않는다.
3. 재생이 검증된 환경에서 상태 관측으로 actor를 지도 학습한다. 절대 목표각
   라벨의 관절 한계 보정량과 급변 시연을 보고한다. 학습/검증을 에피소드로
   나누고, 공통 원본 시연에서 파생된 검증을 OOD라고 부르지 않는다.
4. 초기 actor에서 실제 다중 환경 PPO를 실행한다. 시연 재생, Mimic 생성,
   BC와 PPO의 업데이트 수를 구분한다. 물체 부착이나 강제 상태 이동은 reset
   외에 사용하지 않는다. 물리 검증에 실패한 실험을 확대하지 않는다.
5. 고정된 평가 조건에서 전체 Pick & Place와 실패를 보고한다. 열기, 접근,
   파지, 들기, 운반, 배치, 해제 및 안정 유지가 확인되지 않으면 완료가 아니다.
   영상과 대용량 데이터는 Git에 넣지 않는다.

## 확인된 실행 환경

- Windows: Isaac Sim 4.5 / Isaac Lab 2.1.1, RTX 3060 12GB.
- ASUS 원본 환경 실측: Isaac Sim 5.1.0 / Isaac Lab 2.3.0,
  PyTorch 2.7.0+cu128, RTX 5050 Laptop.
- 원본 HDF5 메타데이터: physics dt=1/60초, decimation=1.
- 원본 위치: ASUS의 `/data/lim/leisaac/datasets/pick_cube_into_box_source_10_20260911.hdf5`.
- Mimic 위치: `/data/lim/leisaac/outputs/mimic_vision224_500_20260913/raw/`.
- 병행 작업이 원격 저장소에서 실행 중이므로 원격 소스/모델을 덮어쓰거나
  타 작업 프로세스를 종료하지 않는다. 별도 출력만 사용한다.

원격 `contract_hardening_20260918/replay_stable_release/evaluation.json`에서
demo_0/1/2의 stable_release_v2 재생 3/3을 읽었다. 이 수치는 기존 작업의
원본 환경 재생 결과이며 새 정책, Windows 환경, 접촉 침투 감사의 통과가 아니다.

## 현재 진행

2026-09-19 재접속 후 원본 성공 10회·5,640프레임과 Mimic 500회·277,447프레임의
숫자 데이터 전송을 완료했다. 두 HDF5의 원격/로컬 SHA-256, 원본 stat 불변,
프레임 정렬을 확인했다. 원본 실패 1회는 manifest에 제외 이유를 남겼다.
환경 코드·자산 154개 파일도 원격/로컬 해시를 대조했다.
근거는 `reports/windows/demo_transfer_20260919.json`이다.

로컬 사본은 `artifacts/demo_warmstart_20260919/`에 있다. RGB 영상은 원본에
남겼다. 사용자가 노트북에서 별도 작업을 시작하므로 이 실행은 노트북 GPU를
추가로 사용하지 않는다. 이후 검증은 받은 사본과 Windows 환경에서 진행한다.
시뮬레이터 버전 차이가 있으므로 원본 환경의 재생 성공을 Windows에 전이하지 않는다.
Windows GPU 물리 재생과 제한 목표각 비교를 실행했다. BC와 병렬 PPO는 아직 실행하지 않았다.

숫자 추출 파일은 원본의 이미지 없는 복사본이며 학습 준비가 끝난 데이터가 아니다.
`demo_action_contract.aligned_targets`는 목표각을 T−1 전이에 정렬하고 범위·급변을
검사하는 유틸리티다. 별도 `isaaclab/scripts/replay_demo_box.py`는 원본 장면의
절대 목표각 재생과 실제 상태·접촉 추적을 수행한다. 학습용 state-action loader,
BC와 PPO 연결부는 아직 구현하지 않았다. 기존 학습 진입점에 이 파일을 입력해 실행하지 않는다.
학습 어댑터는 배열의 6열을 믿고 연결하지 말고 시뮬레이터 관절 이름·순서를
`JOINT_NAMES`와 대조해야 한다. 관절 한계의 출처와 SHA-256도 실행 기록에 남긴다.
범위를 벗어난 목표각은 현재 감사 도구에서 거부한다. 보정이 필요하면 raw를
보존한 별도 파생 라벨에 보정량·제외 기준을 기록하고 재생으로 검증해야 한다.

### Windows 재생·개선 비교 — 2026-09-19

근거: `reports/windows/demo_replay_status_20260919.json`.
모든 실행은 1환경 진단이며 정책 학습이나 독립 평가가 아니다.

| 실행 | 상자 배치·0.5초 안정 유지 | 접촉·손목 진단까지 동시 통과 |
| --- | --- | --- |
| 원본 환경의 기존 3개 시연을 Windows 재생 | 3/3 | 0/3 |
| 손목 목표각 70도 제한 + 종료 자세 1초 유지, 첫 10개 Mimic 시연 | 4/10 | 1/10 |
| 위 10개에서 robot solver position iterations 설정 4→16 비교 | 4/10 | 1/10 |

3개와 10개는 서로 다른 표본이므로 성공률 향상 비교로 사용하지 않는다.
첫 10개는 숫자 추출 파일의 demo_0..9이며 원본 이름의 숫자순 10개가 아니다.
출처는 각 결과의 source_index/source_episode/source_path로 식별한다.
16 설정에서 결과가 개선되지 않았다. 이 비교만으로 유효 solver 반복 수나
시뮬레이터 전반의 성능을 결론내리지 않는다.

반복 재생된 후보 demo_1의 결과:

- 손목 최대 약 70.25도, 큐브 상승 약 0.1617m.
- 손가락–큐브 최대 겹침 약 0.740mm, 손가락–책상 약 0.579mm.
- 상자에 놓은 뒤 최대 1.383초 안정 유지. 원본 220전이 안에서는 안정 유지
  기준을 충족하지 못했고, 추가 종료 자세 유지 60전이 중 기준을 충족했다.
- 양쪽 측면의 하중 접촉을 관찰했다. 다만 열린 접근→닫기→연속 파지·운반→
  제어된 해제의 전체 순서 검증은 아직 끝나지 않았다.
- 실제 변경된 궤적의 pre-step 상태 34개 값과 실행 목표각을 280행 기록했다.
  관측-행동 정렬과 코드 사본 해시를 확인했으며 아직 학습용 데이터 승인은 아니다.

손목 각도는 기존 진단 기준 75도를 유지했다. 이 값 자체가 월드 좌표계에서
손가락이 위로 향한다는 뜻은 아니다. 후보의 링크 자세도 기록했으므로 다음
검증에서는 손가락 진행축과 패드 간격을 함께 확인한다. 단순한 손목각 clipping은
다른 시연의 파지를 깨뜨렸으므로 500개 전체에 일괄 적용하지 않는다.

숫자 감사 재확인: 시간축 `np.diff(target, axis=0)`의 L2 급변 기준 1rad를
넘는 Mimic 시연은 raw 107개, 관절 한계 보정 후 97개다. 나머지 403개도
물리 검증 통과나 학습 적격을 의미하지 않는다. 모든 500개에 기록된 손목각의
최대값이 75도를 넘는 구간이 있어, 원본 에피소드 단순 선별만으로 기존 손목
진단 기준을 충족할 수는 없었다.

다음 실행 순서:

1. 기록된 패드·링크 자세로 후보의 열린 접근, 큐브 끼움, 양면 파지, 운반 중
   접촉, 해제 전후 순서를 검사한다. 현재 normal_grasp_gate_pass는 false다.
2. 같은 기준을 유지하며 손목뿐 아니라 팔 접근 궤적을 함께 보정한다. 파생
   궤적은 실제 재생 상태와 실행 목표각으로 다시 기록한다. 변경한 목표각을
   원본 관측과 섞어 BC 라벨로 사용하지 않는다.
3. 통과 시연과 별도 DemoBox 계약을 확정한 뒤 state actor BC를 실행한다.
4. 64환경 smoke와 실제 GPU PPO 업데이트, 고정 조건 평가를 진행한다.

검증: 관련 테스트 26개 통과(추출 9, 목표각 7, 재생 진단 10), 기존 계약 검사
통과. 전체 테스트는 176개 중 175개 통과이며 기존 영상 카메라 보간 테스트의
부동소수점 정확 일치 비교 1개가 실패했다. 이 실행에서 해당 코드는 바꾸지 않았다.
초기 재생은 결과 저장 뒤 Isaac Lab STOP 콜백의 render loop에서 종료가 멈췄다.
콜백을 해제하고 종료하도록 고친 이후 재생 프로세스의 exit code 0을 확인했다.

## 데이터 접근 재개

원본에는 실패 1회가 섞여 있으므로 성공 10회 추출 때만
`--skip-failed-episodes`를 명시한다. 제외된 시연은 manifest에 남긴다.
500회 raw 묶음은 성공 shard만 선택하고 실패 파일은 별도 보존한다.
모든 출력에는 새 이름을 사용하며, 원본 HDF5·기존 출력·원격 소스를 수정하지 않는다.

HDF5 검사에는 Isaac Sim에 이미 설치된 h5py를 사용한다. Windows의 일반
Python 3.14에는 h5py가 없어 해당 테스트를 실행할 수 없으며, 전역 패키지는 설치하지 않는다.
